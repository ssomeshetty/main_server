Karnataka Politicians Tracker API

v1.0.0 - Bilingual (English/Kannada) Public Tracker

Overview

This API provides access to comprehensive data about Karnataka politicians including:

  • Politician profiles with bilingual content
  • Financial declarations (assets and liabilities)
  • Legal records (criminal cases)
  • Public records (speeches, controversies)
  • Constituency and district information

Note: This API is read-only. All write operations return 405 Method Not Allowed.

Available Endpoints

GET /api/v1/districts/

Lists all districts with optional filtering

GET /api/v1/constituencies/

Lists all constituencies with optional filtering

GET /api/v1/politicians/

Lists all politicians with search and filtering

GET /api/v1/politicians/{id}/

Get detailed politician profile

GET /api/v1/financial-declarations/

Lists all financial declarations

GET /api/v1/legal-records/

Lists all legal records with filtering

GET /api/v1/public-records/

Lists all public records (speeches, etc.)

GET /api/v1/constituency-funds/

Lists all constituency fund allocations

Language Support

All text fields support bilingual content. Use the lang parameter to get Kannada content:

?lang=kn  # For Kannada content
?lang=en  # For English content (default)

Example:

GET /api/v1/politicians/?lang=kn

Pagination

All list endpoints use cursor-based pagination for optimal performance:

GET /api/v1/politicians/?page_size=20
GET /api/v1/politicians/?page_size=50&cursor=cursor_value

Filtering and Search

# Filter by district
GET /api/v1/politicians/?district=1

# Search by name
GET /api/v1/politicians/?search=john

# Filter by constituency type
GET /api/v1/constituencies/?constituency_type=general

# Filter by financial year
GET /api/v1/constituency-funds/?financial_year=2024-25

Authentication

This API is read-only and does not require authentication for public data access.

Warning: Any POST, PUT, PATCH, or DELETE request will return 405 Method Not Allowed.

Rate Limiting

The API is configured with read-only middleware. For production deployment, consider adding rate limiting:

# Example rate limit configuration
DEFAULT_THROTTLE_RATES = {
    'anon': '1000/minute',  # 1000 requests per minute
}

Examples

Get politician by name

curl "http://localhost:8000/api/v1/politicians/?search=rahul" -H "Accept-Language: kn"

Get financial declarations for a politician

curl "http://localhost:8000/api/v1/financial-declarations/?politician=1"

Get constituencies in a district

curl "http://localhost:8000/api/v1/constituencies/?district=1"

Get recent public records

curl "http://localhost:8000/api/v1/public-records/?record_type=speech"
